# Motif 요청 시간 제한과 재시도

## 기준

2026-09-27에 보존된 `omni_v1`의 성공한 수학 풀이 호출 1,107건을 조사했다. 경과 시간의 중앙값은 141초, 90백분위는 280초, 95백분위는 356초, 99백분위는 565초였다. 10분을 넘긴 호출은 11건이며 최대 3,860초였다. 영어 `omni_v2` 재시작 직후 완료된 첫 네 호출은 각각 236·370·24·64초였다. 이 분포를 근거로 정상적인 긴 풀이에도 여유를 주는 **720초(12분)**를 시도 1회당 제한으로 정했다. 이 값은 모델 성능이나 정답률을 바꾸는 기준이 아니라 API 대기 상한이다.

## 동작

- 새 실험 이미지의 `MOTIF_TIMEOUT_SECONDS=720`, `MOTIF_MAX_ATTEMPTS=3`을 사용한다. 풀이와 reflection 모두 적용한다.
- `AsyncOpenAI` 요청 전체에 경과 시간 제한을 적용하고 SDK의 자동 재시도는 0으로 둔다. 네트워크 시간 초과·연결 오류·408/409/429/5xx·빈 텍스트 응답은 별도 기록을 남긴 뒤 다시 시도한다.
- 한 논리 호출에 최대 세 번 요청한다. 모두 실패하면 해당 문제를 수학 오답으로 채점하지 않고 실험을 중단해 Modal의 복구 절차로 넘긴다. 세 번 모두 12분에 걸리면 대기 시간은 약 36분에 짧은 재시도 간격이 더해진다.
- `api_requests.jsonl`은 논리 호출당 한 줄, `api_attempts.jsonl`은 시도마다 시작과 결과를 기록한다. `api_calls.json`의 `provider_calls_this_process`는 모델 요청 시도 수다. `max_api_calls`는 기존과 같이 한 Modal 시도의 논리 호출 상한이며, 재시도까지 포함한 실제 요청 수 상한은 아니다.
- 실패한 시도 뒤 재시도 전에 Modal Volume을 commit한다. 성공 응답은 기존과 같이 다섯 건마다 commit한다. 선점 종료가 진행 중인 요청을 끊으면 완료되지 않은 요청은 새 컨테이너에서 다시 시도한다.

## 기존 실행과 적용 범위

이미 시작된 Modal 함수는 전송 당시의 이미지와 설정을 계속 사용한다. 기존 `en-omni-v2-b600-s0`는 중지했고, 새 데이터·정책을 적용한 `en-omni-v2-clean-b600-t720-s0`를 별도 ID로 시작했다. 재현성을 위한 설정·코드 해시 검사 때문에 기존 ID로 재개할 수 없다. 로컬 `.env`에 `MOTIF_TIMEOUT_SECONDS=1800`이 남아 있으면 로컬 실행에서만 옛 값이 우선하므로 720으로 변경해야 한다.
