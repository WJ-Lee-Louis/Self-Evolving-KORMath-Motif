# 한국어 Omni-MATH 진화용 데이터셋 v1

2026-09-25 기준. 이 문서는 **이미 생성된** `data/omni_v1` 분할을 설명한다. 정확한 원본 행 번호, 제외 사유, 난이도별 개수와 파일 해시는 [manifest](../data/omni_v1/manifest.json)에 있다. 모든 행 번호는 CSV 헤더를 제외한 **0부터 시작하는 번호**다.

## 원본과 제외

원본은 `../datasets/HRM8K/HRM8K/omni-math_do_test.csv`의 1,909행이다. 필드는 `question`(한국어), `answer`(정수 정답), `original`(영어 원문), `question-initial`, `difficulty`다. 이번 실험은 그림 입력이 없는 한국어 텍스트 문제풀이를 대상으로 한다.

| 단계 | 제외 | 남음 |
| --- | ---: | ---: |
| HRM8K Omni-MATH 원본 | 0 | 1,909 |
| 그림·도표·배치 참조 | 39 | 1,870 |
| 부분점수형 추정 문제 | 25 | 1,845 |
| 외부 대회 결과·검색 통계 등 필요 | 9 | 1,836 |
| 문제문에 풀이와 정답 누출 | 1 | 1,835 |
| 잘못된 수식·변수 표기 | 1 | 1,834 |
| GSM8K/MATH와 영어 원문 정확히 일치 | 1 | 1,833 |
| 남은 행에서 영어 또는 한국어 문제문 정확히 중복 | 15 | **1,818** |

그림 참조 39행에는 그림 없이도 답이 정해질 수 있는 **652행**도 포함했다. 첫 수동 감사에서 약 16행을 발견했으나, 그림 표현을 더 넓게 검색하고 각 후보의 한국어·영어 원문을 검토하여 39행으로 늘었다. 그림이 필요 없어 보이는 행도 그림 참조가 있으면 제외했다. `559`행은 풀이가 문제문에 들어 있고, `1391`행은 수식 표기와 변수 조건이 잘못되어 별도로 제외했다. Omni `478`행은 기존 HRM8K/MATH `2816`행과 같아 기존 OOD 평가 집합과의 누출을 막기 위해 제외했다. 원본에 영어 원문 중복 쌍은 16개였으나 `1412`·`1464` 두 행이 모두 그림 문제로 제외되어, 남은 문제의 중복 제거는 15행이다.

그림 이외의 제외도 필요했다. 원본에는 정답 정수 하나를 제공하면서 실제 지시문은 근삿값에 부분점수를 주는 문항과, 외부의 과거 대회 결과를 알아야 하는 문항이 있다. 현재 프로젝트의 **정수 일치 여부** 채점과 맞지 않아 목록에 사유를 남기고 제외했다. 개별 제외 목록은 [quality_flags.csv](../data/omni_design/quality_flags.csv)에서 확인할 수 있다. 이 감사는 규칙 검색과 수동 검토에 근거하므로, 모든 번역 오류나 의미상 중복을 발견했다는 보증은 아니다.

## 난이도와 분할

`difficulty`는 **원본 Omni-MATH 문제에 붙은 숫자형 난이도 메타데이터**다. 이 CSV에 실제로 나타나는 값은 1.0~9.5다. 이전에 언급된 **3.5~6.0**은 중간 난이도만 선택해 보자는 초기 제안의 범위였고, 공식 train·val·test 구분이나 정답 점수가 아니다. 이번 v1은 그 범위로 문제를 제한하지 않고, 정제 후 남은 **전체 난이도**를 사용한다.

정제된 1,818행을 난이도 `<3.5`, `3.5~6.0`, `>6.0`의 세 층으로 나눈 뒤, 각 층에서 고정 시드의 SHA-256 순서로 추출해 **약 70/10/20** 비율로 나눴다. 전체 목표 수는 반올림으로 계산하고, 층별 할당은 최대 나머지 방식이다. 같은 원문이 서로 다른 분할에 들어가지 않는다.

| 분할 | 용도 | 쉬움 <3.5 | 중간 3.5~6.0 | 어려움 >6.0 | 합계 |
| --- | --- | ---: | ---: | ---: | ---: |
| `train` | GEPA 오류 피드백·제안 생성·미니배치 | 310 | 867 | 95 | **1,272** |
| `val` | 진화 중 후보 선택 | 44 | 124 | 14 | **182** |
| `test_id` | 진화 종료 후 초기·최종 프롬프트 비교 | 89 | 248 | 27 | **364** |
| 합계 | | **443** | **1,239** | **136** | **1,818** |

세 분할은 같은 정제된 Omni-MATH 원본에서 왔으므로 `test_id`는 **프로젝트 내부의 동일 출처 보류 집합**이다. HRM8K에서 원래 제공한 test 부분집합을 재분할한 것이므로 HRM8K 공식 test 점수로 보고해서는 안 된다. 다른 데이터셋에 대한 일반화는 기존 MATH 보류 집합 등에서 별도로 확인한다. `val`은 GEPA가 반복해서 참조하므로 최종 일반화 성능은 `test_id`로 판단한다. 난이도 구간별 점수도 함께 보고하여 중간 문제의 개선이 쉬운 문제의 높은 점수에 가려지지 않게 한다. 어려운 구간의 `val` 14행과 `test_id` 27행은 개수가 작으므로 해당 구간의 점수 변화는 신중히 해석한다.

## 재생성·실행 연결

```powershell
.\.venv\Scripts\python.exe .\scripts\prepare_omni_splits.py --check
.\.venv\Scripts\modal.exe run .\modal_experiment.py::preflight --dataset omni_v1
```

재생성하려면 `--check`를 빼면 된다. 원본 파일과 수동 제외 목록의 해시를 manifest에 기록한다. `modal_experiment.py`는 `--dataset omni_v1`을 받아 이 분할을 전송하며, 기존 실험을 위한 기본값 `hrm8k_v1`도 유지한다. 새 실험에는 새 `run-id`를 사용한다. **182개 `val`을 처음 평가하므로 `max-metric-calls`는 182보다 커야 하며**, 실제 반복 진화에는 그보다 충분히 큰 예산이 필요하다. 이 문서 작성 과정에서 Motif API 진화는 실행하지 않았다.

### 난이도별 미니배치

Omni-MATH에서는 `--minibatch-size 5`일 때 기본 `--batch-sampling auto`가 `omni_difficulty_1_3_1`을 선택한다. 매 진화 반복에 **쉬움 1·중간 3·어려움 1**을 뽑는다. 각 난이도 집합의 문항은 시드와 GEPA 반복 번호로 정해지는 SHA-256 순서로 한 번씩 사용한 뒤 다시 섞는다. 어려움 문항은 95개뿐이므로 95회 이후 다음 순환을 시작한다. 순서와 비율은 중단 후 재개에도 동일하다. 기존 GSM8K 실행은 종전의 GEPA `epoch_shuffled` 방식이다.

```powershell
.\.venv\Scripts\modal.exe run --detach .\modal_experiment.py::optimize --dataset omni_v1 --run-id ko-omni-b1200-m5-s0 --minibatch-size 5 --batch-sampling omni_difficulty_1_3_1 --max-metric-calls 1200 --max-api-calls 1800 --seed 0
```

위 명령은 1,200회 GEPA 평가 예산과 프로세스당 1,800회 논리 API 호출 상한을 둔 Omni-MATH 실행 설정이다. 이전에 문서에 있던 `600/850`은 더 작은 예시 예산이었으며, 위 명령과 혼동하지 않도록 교체했다. `config.json`과 `run_manifest.json`은 추출 방식·비율·시드·코드 사본을 고정하고, `events.jsonl`의 각 `minibatch` 이벤트는 실제 문항 ID와 난이도를 남긴다. `val` 182문항의 자연 분포와 `test_id` 364문항은 변경하지 않는다. 초기 프롬프트 및 미니배치 심사를 통과한 후보의 검증 점수는 종전처럼 기록한다.

Modal 한 번의 실행은 최대 24시간이다. 초기 검증 182문항은 GEPA 상태가 처음 저장되기 전에 진행되므로, 특히 이 단계가 길어질 수 있다. 시간 초과 시 최대 10회 자동 재시도하고, 5회마다 Volume에 확정한 성공 응답은 다음 시도에서 재사용한다. 마지막 commit 이후의 몇 건은 다시 호출될 수 있다. 개별 API 호출은 현재 1,800초 제한과 SDK 재시도 2회를 가지며, 제공자 장애나 재시도 10회 소진까지 막을 수는 없다. `--detach`는 PC 종료 후에도 Modal 실행을 유지하지만 24시간 제한을 없애지는 않는다. [실험 실행 문서](EXPERIMENT_RUN.md)에 복구 동작을 더 적었다.

현재 채점기는 마지막 줄의 `정답: 정수` 형식을 요구한다. 진화 실행 전에 정수 추출·형식 오류 처리 방식을 고정하고 초기 프롬프트와 최종 프롬프트에 동일하게 적용해야 한다. 비용이 큰 실험을 시작하기 전 남은 비시각적 품질 결함을 추가로 점검할 여지도 있다.
